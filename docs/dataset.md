# Dataset Schema and Format

This document describes the output layout produced by the scripts in this
repository.

---

## Positive samples — `wakes/`

Each file is a 16 kHz, mono WAV recording of the target wake word spoken once.

| Field | Value |
|---|---|
| Sample rate | 16 000 Hz |
| Channels | 1 (mono) |
| Format | WAV (PCM 16-bit) |
| Naming | `<wakeword>_<speaker_id>_<index>.wav` |

---

## Negative samples — `negatives/`

Audio clips that do **not** contain the wake word.  Populated from two sources:

1. **Adversarial text** — phonetically confusable phrases generated by
   `adversarial_samples.py` and synthesised with the same TTS pipeline.
2. **Background / ambient audio** — silence, noise, or unrelated speech
   (added during the augmentation stage).

---

## Metadata file — `metadata.csv`

A flat CSV with no header row:

```
<relative_audio_path>,<label>
```

| Column | Type | Description |
|---|---|---|
| `path` | `str` | Relative path to the WAV file from the dataset root |
| `label` | `int` | `1` = wake word present, `0` = negative sample |

Example rows:

```
wakes/hey_jarvis_spk0_000.wav,1
negatives/hay_jarvis_spk0_000.wav,0
negatives/background_000.wav,0
```

---

## Augmented dataset — `*_aug/` + `metadata.csv`

Running `augment.py` on a base dataset produces a parallel directory tree:

```
augmented_data/
  wakes_aug/          # augmented positive samples
  negatives_aug/      # augmented negative samples
  metadata.csv        # same schema as above, paths updated to *_aug/
```

Each augmented WAV is peak-normalised.  The augmentation parameters (SNR
range, pitch range, speed range, reverb probability) are all configurable
via CLI flags; see `python augment.py --help`.

---

## Adversarial word list — `<wakeword>_adversarial.txt`

One confusable phrase per line, lower-cased, deduplicated.  Generated by
`adversarial_samples.py` and post-processed by `normalize_txt.sh`.  This
file is consumed as input to the TTS synthesis step to produce negative
samples.

---

## HuggingFace publishing

Datasets built with this pipeline follow the `audiofolder` structure
expected by `datasets.load_dataset("audiofolder", ...)`.

Recommended card metadata:

```yaml
task_categories:
  - audio-classification
tags:
  - wake-word
  - ovos
  - synthetic
  - voice-conversion
language:
  - <BCP-47 code>
license: apache-2.0
```
